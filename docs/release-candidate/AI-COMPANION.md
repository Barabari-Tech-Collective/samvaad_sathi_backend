# AI companion and interviewer — planned build

Status: approved for the roadmap; not implemented. This is a Samvaad product character, not a Codex pet integration.

## Build placement

Complete scoped coaching workflows and interview recovery/audio state contracts first. Then design and validate the character during the responsive design-system phase, integrate practice first, and introduce neutral assessment presentation only after practice accessibility/device acceptance. It does not block current access-control and assignment builds. Provider/media integrations remain separately gated.

## Experience

One recognisable blue/yellow character, with a small approved name selection and clear AI identification. Practice behaviour is supportive, with specific progress encouragement and optional animation/voice. Assessment behaviour is composed and neutral: no reactions that imply scoring, coaching, hints or emotion judgments. Clearly distinguish human participants and suspend AI speaking during human ownership.

## Implementation sequence

1. Approve character/face/name direction and responsive compositions using Inter, Poppins and Noto Sans Devanagari with the existing palette.
2. Build lightweight SVG states: idle, greeting, listening, thinking, speaking and reconnecting. Drive states from real microphone, request and playback events. Never imply the mic is listening while disconnected. Video generation is not required.
3. Integrate practice greetings, exercise explanations and evidence-based encouragement. No fabricated progress, streak pressure, accent judgments or therapeutic claims.
4. Add assessment presentation with neutral expressions, the same immutable questions/count engine, clear AI/human speaker labels and one active turn owner. Character state cannot change scoring or interview policy.
5. Verify reduced motion, hide/mute preferences, screen-reader text state, keyboard controls, slow devices, denied microphone, blocked autoplay, interrupted playback, disconnect/reconnect and human handover. No animation interruption of active answers.

Acceptance: usable with the character hidden; accurate audio states; no secrets or sensitive answers in character preference storage; no assessment hints; no additional model calls required for expressions. Review practice before assessment rollout. Multiple characters and extensive customisation are later work.
